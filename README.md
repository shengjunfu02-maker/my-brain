# iwork —— 个人随身资料库（先读我）

> 这是一份自包含的个人资料包。无论是什么 AI、在什么环境运行，只要用户把这个仓库给你，你就应该能看懂全部内容并执行里面的工作流。本文件是入口，请先通读，再按任务需要打开对应文档。

## 一、这是个什么库（背景，必读）

- 这是一个**个人生活与工作的随身资料库**：用来随手记录、整理名单联系人、沉淀各类模板与日报，把零散信息归纳成可复用的结构。
- 核心用法：随时记录 → 按模板整理 → 定期归纳汇总。
- 沟通语言：中文。所有产出（表格、名单、日报）都用中文。

## 四、通用规则（任何任务都适用）

1. **数据是事实来源**：联系人的情况、检测读数一律以 `数据/` 里的文件为准；不要凭印象编造信息或读数。
2. **路径用相对路径**（相对本仓库根目录），不要假设绝对路径。
3. **追加型文件只追加、不覆盖历史**（水质检测记录.csv、拜访记录汇总.xlsx）。
4. **格式保持一致**：每个文件的列结构、命名风格、分类口径都已定型，新增内容严格沿用。
5. **合并规则**：人名、品牌/项目名与表内已有条目发音相似的，视为同一个直接合并，不用问；明显不同的才新增。
6. **不擅自定性**：日常联系一律记"客情走访"；"新联系人"由用户自己标注，AI 不主动下结论。
7. **每日日志规则**：每天新建 `日志/YYYY-MM-DD.md`。白天收到信息**只追加到当天日志文件，不要同时动摸牌表**（避免重复写、浪费 token）；每天晚上 18:30 统一把当天日志归纳合并进 `数据/用户摸牌表.xlsx` 和 `数据/养殖客户拜访记录汇总.xlsx`，并产出当天工作汇报。日志文件保留作存档。后续查信息一律先查摸牌表，不要翻历史日志。
8. **走访读写优先级（仅限联系人走访）**：涉及当天走访的读取，必须先读当天 `日志/YYYY-MM-DD.md`，掌握尚未归纳的最新动态；写入一律优先写入当天日志文件，日终归纳时再沉淀进 `数据/`。其他任务不受此限，仍按第三节工作流索引的大标题对应文档执行。
9. **依赖环境**：照片读数需要 Python + 图像/数值处理库；读写 xlsx 需要 pandas + openpyxl。环境缺库先安装再执行。
10. **硬性规则（务必遵守）**：本仓库**刻意保持公开**，目的就是让任意 AI、任意对话都能直接访问并执行里面的工作流，不要主动建议或询问"是否私有化 / 是否脱敏隐藏 / 是否改私有"等同类问题；也不要擅自做隐藏、删除或限制访问的操作。
11. **汇报规则（潜规则，不是纪律）**：用户抓鱼（出鱼）期间在忙、顾不上理人，这是行业潜规则常识，不是什么死纪律。写每日汇报时直接写「抓鱼，择日再访」就完事，不必解释原因、别写「按纪律不拜访」那套；工作日志怎么记都行，但汇报出去要简洁。
12. **每日问题规则**：每天新建 `每日问题/YYYY-MM-DD.md`。拜访后回想起、当时没来得及问/说的话，随时追加到当天每日问题文件，只记录不汇总、不覆盖历史；涉及具体养殖户的写明对象，方便后续走访带上。与日志并列，互不替代。
13. **新对话启动自检**：每次开启新对话、读完本文件后，先检测当天 `日志/YYYY-MM-DD.md` 是否记录了当日走访，再检测 `数据/用户摸牌表.xlsx` 与 `养殖客户拜访记录汇总.xlsx` 是否已归纳该日内容；若日志有内容但摸排表尚未归纳、且当前时间早于当天 18:30（傍晚6:30），则直接在新对话里执行归纳（按第7条合并进数据表并产出汇报）；若摸排表已归纳过则跳过，不重复写。
14. **摸排表写入权限（对不上的先记账，动表先问）**：当天收到的数据与 `用户摸牌表.xlsx` 对不上的（新增用户、改名、改品牌、改经销商、改等级等），一律先记到当天 `日志/YYYY-MM-DD.md`，等晚间 18:30 归纳时统一处理，白天不动物牌表；若确有特殊情况必须在非归纳时间把数据上传到摸排表，须先征得本人同意，不得擅自落盘。

## 五、日报写作禁忌（详见 `模板与汇报/工作汇报模板.md`）

- ❌ 正文出现括号注释（有括号内容直接整段删掉）
- ❌ 心得里写"走访X户"之类的户数统计
- ❌ 心得分点写（一两句话即可）
- ❌ 写正常项的数据凑篇幅（只写有异常的项）
- ❌ 把外部/竞品的效果说成自己产品的效果

## 六、常识速查

- **⚠️ 报警线**：检测值超过约定阈值即标 ⚠️；接近阈值的临界项也是回访的天然由头。
- 记录异常项时，优先标注数值与对象，便于后续跟进。
