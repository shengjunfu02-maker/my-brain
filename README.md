# my-brain —— 随身资料入口（先读我）

> 这是一份自包含的个人工作资料包。无论是什么 AI、在什么环境运行，只要用户把这个仓库给你，你就应该能看懂全部内容并执行里面的工作流。本文件是入口，请先通读，再按任务需要打开对应文档。

## 一、用户是谁（背景，必读）

- 用户是**通威（水产饲料/动保）业务员**，负责海南文昌片区（锦山镇、抱罗镇、冯坡镇、大致坡等）的养殖户开发与维护。
- 核心工作：走访养殖户 → 测水（pH、氨氮、亚硝酸盐）→ 建立客户档案 → 推动换料/成交 → 定期汇报。
- 行业铁律：**客户抓鱼（出鱼）期间不拜访、不推销饲料**，出鱼后再联系。
- 称呼铁律：**客户＝经销商（拿料的）；用户＝终端养殖户（喂鱼的）**。日志里拜访的人名都是用户，不要混用。
- 沟通语言：中文。所有产出（表格、名单、汇报）都用中文。

## 四、通用规则（任何任务都适用）

1. **数据是事实来源**：客户情况、水质读数一律以 `数据/` 里的文件为准；不要凭印象编造客户信息或读数。
2. **路径用相对路径**（相对本仓库根目录），不要假设绝对路径。
3. **追加型文件只追加、不覆盖历史**（水质检测记录.csv、拜访记录汇总.xlsx）。
4. **格式保持一致**：每个文件的列结构、命名风格、分类口径都已定型，新增内容严格沿用。
5. **合并规则**：人名、饲料品牌名与表内已有条目发音相似的，视为同一个直接合并，不用问；明显不同的才新增。
6. **不擅自定性**：日常拜访一律记"客情走访"；"新用户"由用户自己标注，AI 不主动下结论。
7. **每日日志规则**：每天新建 `日志/YYYY-MM-DD.md`。白天收到走访信息**只追加到当天日志文件，不要同时动摸牌表**（避免重复写、浪费 token）；每天晚上 18:30 统一把当天日志归纳合并进 `数据/用户摸牌表.xlsx` 和 `数据/养殖客户拜访记录汇总.xlsx`，并产出当天工作汇报。日志文件保留作存档。后续查客户信息一律先查摸牌表，不要翻历史日志。
8. **走访读写优先级（仅限客户走访）**：涉及当天走访的读取，必须先读当天 `日志/YYYY-MM-DD.md`，掌握尚未归纳的最新动态；写入一律优先写入当天日志文件，日终归纳时再沉淀进 `数据/`。测水、资料学习等其他任务不受此限，仍按第三节工作流索引的大标题对应文档执行。
9. **依赖环境**：水样读数需要 Python + Pillow + numpy；读写 xlsx 需要 pandas + openpyxl。环境缺库先安装再执行。
10. **每日问题规则**：每天新建 `每日问题/YYYY-MM-DD.md`。拜访后回想起、当时没问出口的问题或没说出口的话，随时追加到当天每日问题文件，**只记录不汇总、不覆盖历史**；涉及具体养殖户的写明对象，方便后续走访带上。与日志并列，互不替代。

## 五、日报写作禁忌（详见 `模板与汇报/工作汇报模板.md`）

- ❌ 正文出现括号注释（有括号内容直接整段删掉）
- ❌ 心得里写"走访X户"之类的户数统计
- ❌ 心得分点写（一两句话即可）
- ❌ 写正常塘的测水数据凑篇幅（只写有问题的塘）
- ❌ 把竞品饲料的效果说成通威产品的效果

## 六、业务常识速查

- **⚠️ 报警线**：亚硝酸盐 ≥ 0.3（接近 0.28 即标 ⚠️）；氨氮 ≥ 5 标 ⚠️。临界塘口是复检回访的天然由头。
- 阴雨天氨氮/亚盐易偏高：光照弱 → 硝化受抑。
